# Agent 运行时与核心架构

## 一、LLM 原理与能力边界

### Transformer 架构要点
- **注意力机制**：Self-Attention 计算 Q·K^T·V，复杂度 O(n²·d)
- **KV Cache**：推理时缓存历史 token 的 K/V，避免重复计算；前缀缓存（Prompt Caching）复用公共前缀
- **上下文窗口**：模型最大输入 token 数；实际可用 = 窗口 - 输出预留 - 系统提示
- **token 计费**：输入 token + 输出 token 分别计价；思考 token（reasoning_content）也计费

### 模型能力边界
- **何时该用工具**：需要实时数据、精确计算、文件操作、外部 API → 工具
- **何时靠模型自身**：文本生成、摘要、翻译、代码生成、知识问答 → 模型
- **幻觉检测**：模型对不知道的事实容易编造；Function Calling 可降低幻觉（结构化输出约束）

### 标准模型 vs 推理模型
- **标准模型 / 对话模型**（qwen-plus, gpt-5.5, deepseek-v4-flash 关闭思考）：直接输出回答，无显式思考过程
- **推理模型 / 思考模型**（deepseek-v4-pro 开启思考, GPT-5.6 Sol, Claude Fable 5, Claude Opus 5, qwen3.7-max 思考模式）：先输出 reasoning_content（思考过程），再输出正文
- **工程处理**：reasoning_content 走单独通道，不展示给用户（或折叠显示），不进入 TTS
- **注意**：现在面向用户的模型都经过指令微调（Instruct Tuning），"指令模型"一词已无区分意义，真正的区别在于是否有显式思考链
- **2026 年 8 月推理模型格局**：
  - DeepSeek V4 Pro（low/high/max 三档思考强度，2026-08-13 正式版）
  - OpenAI GPT-5.6 Sol（2026-06-26 发布，推理+编码旗舰）、o3 Pro（硬推理）
  - Anthropic Claude Fable 5（2026-06，最深层推理）、Claude Opus 5（2026-07，前沿推理+智能体）
  - Qwen3.7-Max（标准/思考双模式）
  - Google Gemini 3.1 Pro

## 二、Prompt 工程

### System Prompt 五层结构
1. **角色锚定**：定义 AI 身份、性格、说话风格
2. **背景注入**：项目上下文、用户信息、环境状态
3. **能力枚举**：可用工具列表及使用规则
4. **工具规则**：何时调工具、参数格式、错误处理
5. **SOP 编排**：标准作业流程，如"先查文件再改代码"
6. **风格约束**：输出格式、语言偏好、长度限制

### Few-shot vs Zero-shot
- **Zero-shot**：靠指令描述任务，适合简单任务
- **Few-shot**：给 2-5 个示例，适合复杂格式或需要模仿风格
- **工程权衡**：Few-shot 消耗更多 token，但准确率更高；前缀缓存可降低成本

### 结构化输出
- **JSON Schema**：定义工具参数的 JSON Schema，模型按 schema 输出
- **function calling**：模型输出 `{"name": "tool_name", "arguments": {...}}`
- **流式解析**：参数是增量生成的（`input_json_delta`），需要累积拼接再解析

## 三、Agent 运行时模式

### Function Calling（函数调用）
- **本质**：模型声明可用工具列表及参数结构，根据用户意图自动输出结构化函数调用指令
- **特点**：单步任务、参数提取精准
- **比喻**：一个精准的"翻译官"，把用户需求翻译成函数名+参数

### Tool Calling（工具调用）
- **本质**：Function Calling 的工程化升级，支持更广泛的工具类型（API、数据库、代码解释器）
- **特点**：多工具串联、多轮递归调用、会话状态留存
- **比喻**：一个万能的"调度中心"，自主决定何时调用、调用哪个、如何组合

### ReAct（Reason + Act）
- **本质**：推理与行动交替的循环：Thought → Action → Observation → Thought → ...
- **特点**：多步推理、自我纠错、可解释过程
- **与 Function Calling 的区别**：
  - Function Calling：单步决策，模型直接输出工具调用
  - ReAct：多步推理循环，每步先思考再行动，可观察结果后调整
- **适用场景**：需要"想一步做一步"的复杂任务，如"查天气→判断是否需要带伞→提醒用户"

### Plan-Execute（规划-执行）
- **本质**：先规划完整步骤列表，再逐步执行
- **特点**：可预见性强、适合确定性任务
- **与 ReAct 的区别**：ReAct 边想边做，Plan-Execute 先想好再做

## 四、流式工具调用工程实现

### 流式解析核心难点
- 模型流式输出时，工具调用参数是增量生成的
- 例如：`{"name": "wri` → `ter", "ar` → `guments": {"` → `text": "hello"}}`
- 需要**累积拼接** `input_json_delta`，直到参数完整再解析

### 输出截断自动续写
- 当模型输出达到 max_tokens 限制时会被截断
- 检测到截断后，自动发送续写请求（`continue` 或空消息）
- 续写结果拼接到原始输出后

### 工具结果处理
- **截断落盘**：工具输出超过阈值（如 20K 字符）时，存到文件，只回灌摘要
- **图片提取**：JSON 输出中提取图片路径，base64 编码后作为 ImageContent 回传
- **非 UTF-8 容错**：用 `errors="replace"` 解码，避免编码异常

## 五、上下文管理

### 上下文压缩策略

#### 水位触发机制
- **三档水位**：30%（轻度压缩）、60%（中度压缩）、80%（激进压缩）
- **触发条件**：当前 token 数 / 上下文窗口 ≥ 水位阈值
- **压缩策略**：
  - 轻度：折叠工具结果（只保留摘要）
  - 中度：摘要历史消息（N 条 → 1 条摘要）
  - 激进：丢弃最旧消息，只保留最近 K 条 + 摘要

#### 结构化摘要提示词
九段结构：用户请求 / 技术决策 / 文件代码 / 错误修复 / 用户反馈 / 消息列表 / 待办 / 当前状态 / 下一步

#### 压缩后回灌
- 压缩后的摘要作为新消息注入上下文
- 相关文件路径回灌（最多 5 个文件 / 5000 字符）
- 图片剥离（不回灌图片，只保留路径引用）

### 会话持久化
- **恢复点**：定期保存会话快照到 `.jarvis/SESSION_MEMORY.md`
- **崩溃恢复**：启动时检测异常退出，提示是否恢复
- **原子性**：恢复点写入用临时文件 + rename，避免写一半崩溃

### 长期记忆
- **MEMORY.md**：项目级长期记忆（用户偏好、项目约定）
- **~/.workbuddy/MEMORY.md**：跨项目用户习惯
- **注入策略**：每次会话开始时读取并注入到 system prompt
